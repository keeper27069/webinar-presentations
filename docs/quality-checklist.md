# Чек-лист готовности урока

Пройди по пунктам перед PR. Исправляй найденное, а не перечисляй его пользователю.

## Содержание и педагогика
- [ ] Урок выполняет описание из учебного плана (`topics.md`) — каждое «ученик поймёт / научится» закрыто конкретной сценой.
- [ ] Есть главный вопрос; в первой сцене чат отвечает на него, в финале ответ раскрыт.
- [ ] Есть явная связь с навыком текущего модуля.
- [ ] Сцен: 14–15 (общая) или 10–12 (техническая); у каждой своя цель, метафора, механика; нет двух одинаковых механик подряд; «выбери вариант» — не больше 2 сцен.
- [ ] 3–5 сцен со слоем ⭐ для старших.
- [ ] Факты, цифры, версии и синтаксис проверены (код в `LiveCode` реально работает так, как сказано).
- [ ] Учебные упрощения не выдаются за точное устройство технологии.

## Стрим и ведущий
- [ ] У каждой сцены заметки: `say` (2–5), вопрос чату, ожидаемые ответы, правильный ответ/разбор, минуты; где нужно — `switchTo`.
- [ ] Сумма минут ≈ запланированной длительности эфира.
- [ ] На экране ≤ ~25 слов основного текста на сцену; всё длинное — в заметках.
- [ ] Минимальные размеры шрифтов и целей соблюдены (см. архитектуру, раздел 3); нижние 120px без важного.
- [ ] Любой вариант чата ведёт к осмысленному результату; сброс (R) работает; тупиков нет.
- [ ] Окно ведущего (P) синхронно листает сцены.

## Языки
- [ ] `ru`, `uz`, `en` заполнены полностью (TypeScript не ругается).
- [ ] Узбекский — латиница с правильными `ʻ`/`ʼ`, естественный разговорный язык для подростков, IT-термины как их реально говорят.
- [ ] На скриншотах `uz` текст не обрезан и не вылезает.

## Безопасность
- [ ] Зрителей не просят писать в чат личные данные, пароли, адреса, фото.
- [ ] Темы про безопасность — только защитная сторона; поддельные сайты — вымышленные бренды, формы никуда не отправляют данные.
- [ ] Иллюстрации оригинальные, без фирменных логотипов реальных сервисов.
- [ ] Урок не пугает и не внушает слепого доверия/недоверия к технологиям.

## Техника
- [ ] `npm run typecheck` и `npm run build` — без ошибок.
- [ ] `npm run smoke -- <id>` — без ошибок консоли, выхода за кадр, «вылезания» из тела сцены (перекрытие вывода) и тупиков на всех трёх языках. Скрипт сам прокликивает кнопки каждой сцены и проверяет состояние после кликов.
- [ ] Если в песочнице нет доступа к npm — запушь ветку и дождись GitHub Actions (`.github/workflows/ci.yml`): там typecheck, build и smoke; скриншоты — в артефакте `smoke-screenshots`.
- [ ] Скриншоты просмотрены глазами: минимум сцены 1, центральная, одна кодовая (если есть), финальная — на `uz`.
- [ ] Урок зарегистрирован в `registry.ts` со статусом `ready`, виден в каталоге и открывается по прямой ссылке.
- [ ] Если в движок добавлен компонент — он описан в `src/engine/ENGINE.md`.
